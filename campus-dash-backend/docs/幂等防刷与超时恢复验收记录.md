# 幂等、防刷与超时恢复实现记录

日期：2026-10-20。对应方案：[幂等防刷与超时占位恢复技术方案](幂等防刷与超时占位恢复技术方案.md)。本记录说明首次实现的本地验收范围，不代表已经上线；后续修复与最新验证见 [竞态复核记录](幂等与超时竞态复核记录.md)。

## 已实现的行为

| 范围 | 当前实现 |
| --- | --- |
| 持久幂等 | `grab_request` 以校区、跑腿、操作、请求 UUID 唯一；固定参数指纹、轮次和执行令牌；DB 签发 30 秒不可续租期限；终态重放与独立结果查询 |
| 原子提交 | 请求行锁后重新取 DB 时间；带状态、版本、轮次与名额条件的 CAS；占用记录双唯一索引及请求记录唯一关联；首轮超时消息、请求终态和投影任务在同一事务提交 |
| 提交不确定 | COMMIT 异常回主库查原请求；DB 不可达返回 503 并保留 ID；已提交成功不因通知/缓存异常撤销 |
| Redis v2 | 单任务 Hash 分离已提交事实和临时 pending；按 DB 版本应用；同版本保留在途占位；精确撤销与墓碑；INIT/READY 令牌重建；不用 INCR/DECR 修复数量 |
| 后台恢复 | 请求到期扫描；持久 repair 任务租约领取、令牌完成、退避重试和 DEAD；固定上界、按校区/状态有界巡检；DONE 任务遇到再次损坏可重开 |
| 状态机 | 待抢单 → 抢中待确认 → 待取货 → 配送中 → 待确认完成 → 已结算；确认超时可转下一候选或回池；取消/争议/退款保留独立合法分支 |
| 实际到期判断 | `confirm_deadline` 使用数据库时钟；取到行锁后确认要求未到期，流转/回池要求到期；确认绑定客户端轮次；旧轮次和重复消息无副作用 |
| 候选 | 条目绑定轮次与令牌，先 peek、转交提交后精确删除；按回池周期隔离并计算流转预算；重新检查信用及在途门槛；入队仍为尽力而为，响应不保证固定名次 |
| 跑腿防刷 | 可信跑腿 ID 的个人桶与个人/任务桶在同 Lua 内先检查后扣减；每次 HTTP 请求均计费；查询独立预算、本机并发上限与故障回退 |
| 网关 | 独立 Spring Cloud Gateway；路由/IP 桶共享 Redis，错误关闭写入；429/503 + Retry-After；不信客户端身份头；内部 API 不经公网网关 |
| 身份 | 演示登录默认关闭；local/test/bench 显式开启；生产配置守卫；JWT/Session demo-live 隔离；标准 OIDC 授权码 + PKCE、issuer/sub 服务端映射 |
| 前端 | 身份隔离的 sessionStorage 固定 UUID/轮次；刷新后恢复；最多 3 轮自动恢复；202/429/503/网络异常不换 ID；重放成功后刷新当前详情与动作 |

新任务只允许 `slotTotal=1`。历史多名额记录不被迁移脚本擅自改写，新抢单拒绝继续使用该旧模型。`PUBLISHED` 表示尚无人占用，不能描述为“未接单 N 分钟后释放占位”；释放的是过期的请求 pending 或 `LOCKED` 确认占位。

## 关键代码入口

- 应用：`GrabErrandUseCase`、`GrabRequestStep`、`GrabTransactionalStep`、`GrabProjectionSync`、`GrabRecoveryUseCase`。
- 生命周期：`ErrandLifecycleStep` 将确认/取货/送达/争议的数据库事务与提交后通知拆开；发布事务拆为 `PublishErrandStep`。
- 仓储：`JdbcErrandRepository` 所有状态 CAS 与对应投影任务同事务，覆盖结算、退款、取消和仲裁旁路。
- Worker：`GrabRecoveryJob`、`TimeoutScanJob`、`TimeoutTransferConsumer`。旧数值 ID 与新字符串 ID 消息都可解析，非法 payload 记录错误后 ACK。
- 基础设施：[占位恢复说明](占位恢复实现说明.md)、[网关与身份说明](网关与身份接入说明.md)。

## 迁移、启用和回滚

1. 备份并检查历史多名额、LOCKED 缺少 `locked_at`、缺少截止时间的数据。历史不完整行需人工处理，不按当前时间凭空生成历史期限。
2. 关闭所有任务写入口，排空在途请求，停止旧 app/worker。不能同时运行旧 INCR/DECR 协议与 v2。
3. 在同一个数据库会话里显式设置历史确认窗口后执行可重复迁移；本地已有库按原 300 秒配置回填。

   ```sql
   SET @legacy_confirm_timeout_seconds=300;
   SOURCE docker/migrate-grab-reliability.sql;
   ```

4. 配置新 app/worker/gateway、真实身份与内部凭证；先运行恢复任务并观察 DB/Redis 状态差异，再开放新写入口。新库直接使用 `docker/init.sql`。
5. 回滚应先关闭写入口并停新进程。保留 `grab_request` 及补偿/消息事实，旧程序不会理解这些执行记录；优先回滚业务外观或修复 v2，不能删除表后将原请求当新请求重放。恢复旧协议必须另做数据导出、占位初始化与停止混写演练。

`docker/docker-compose.ingress.yaml` 给出仅发布网关业务端口的容器结构；本地单进程绑定默认地址与可信代理配置见身份接入说明。模板没有替代实际网络策略验证。
