# 幂等、超时释放与并发抢单复核

日期：2026-10-20。范围为上一轮实现的请求幂等、订单 CAS、确认超时、候选队列、Redis 投影恢复及前端确认协议。以下记录已发现的问题、修复和验证范围；不把本地测试等同于生产演练。

## 已修复的问题

| 问题 | 可复现的时序与影响 | 修复 |
| --- | --- | --- |
| 行锁等待跨过截止时间 | 确认 UPDATE 在截止前进入数据库、在行锁上等待到截止后；MySQL 的 NOW 仍是语句开始时间，可能放行迟到确认。首次抢单/流转也可能从等待前开始计算确认窗口 | 先在同一事务内按主键取行锁，再执行带数据库时间判断的 CAS；等待结束后重新取时间 |
| A → B → A 的迟到确认 | 旧确认只携带订单和跑腿 ID，A 再次成为占用者后，第一轮请求可能确认新的占位 | HTTP 确认强制 `expectedRound`；前端发送点击时的轮次；应用在幂等返回前检查轮次 |
| 重复超时消费者误回池 | 消费者 1 先弹出唯一候选但尚未提交，消费者 2 看到空队列并先回池，候选失去本轮接单机会；弹出后宕机也会丢资格 | 先 peek，DB CAS 提交成功后按条目令牌删除；CAS 失败保留条目，不用重新入队改变顺序 |
| 候选跨回池周期污染 | 旧请求在回池后才入队，或者旧条目挡住同跑腿新轮次报名；迟到清理还可能删除新条目 | 候选绑定请求轮次和令牌；最近 PUBLISHED 日志轮次作为周期下界；新轮次替换旧条目，同轮次保留顺序；精确删除避免 ABA |
| 流转预算永久耗尽 | 全局 round 单调增长，达到最大流转次数后，后来每次回池重抢也会直接回池 | 最大流转次数按 `round - cycleRound` 判断，全局 round 保持单调 |
| 损坏占位阻塞巡检 | 一条未知或损坏 pending 保持当前页水位不动，后续页订单永远无法被巡检 | 异常订单持久登记为独立 AUDIT_PROJECTION 任务后继续扫描；登记也失败才保留水位，重试耗尽转 DEAD，不盲目删除未知占位 |
| 消息状态被迟到失败回退 | 两个发送者读取同一 PENDING，先成功者标记 SENT，后失败者又改成 PENDING/DEAD；SET 自增顺序还会提前耗尽重试次数 | 重试只更新 PENDING，先计算状态和退避再自增；已成功状态不可被失败回写覆盖 |
| 后端允许发单人自抢 | 前端隐藏抢单按钮，但直接请求接口仍可抢自己的任务 | 用例入口与最终事务步骤双重校验，拒绝结果持久化并可幂等重放；候选选择也排除发单人 |
| 突发抢单饿死处理中请求 | 全量测试中 2000 个不同跑腿请求同时争用 20 个数据库连接，获得 Redis 占位的请求也可能取连接超时，导致这一波成功数为 0 | 共享限流之后、首次 DB 访问之前增加本机在途并发上限；超限返回 503 和 Retry-After，保留原请求 ID；所有出口归还容量，查询使用独立容量 |

候选队列仍是尽力而为的偏好队列，不承诺固定排名。一次最多清理 32 个失效条目；清理预算用完只交给下一轮扫描，不将“尚未检查完”当成“队列为空”。

本机在途并发配置为 `dash.grab.max-in-flight`，默认 10；按实例数据库连接预算设置，并为查询与其他接口预留余量。它不是分布式锁，也不参与订单唯一归属裁决。

## 再次验证的正确性约束

- 同一持久请求的执行、过期处理由请求行锁串行化；请求重试不续租，不重新抢占执行权。
- 请求已持锁但订单 CAS 长时间阻塞、超过请求租约后，最终终态更新失败会回滚订单、占用记录、状态日志、超时消息及投影任务；回收完成后新请求可继续抢单。
- 登记提交后首次回读失败，响应为 503；同 ID 重试读取原 PROCESSING，等待固定租约终结，不另开一次执行。
- COMMIT 响应异常仍以主库结果为准；通知和投影异常不能撤销已经提交的占用。
- Redis 的版本单调、同版本 pending 保留、精确令牌撤销、重建租约及补偿 workerToken 防护继续保留。

## 接入变化与边界

确认接口现在强制请求体 `{"expectedRound":当前显示轮次}`；不允许后端替旧请求自动填入新轮次。内部历史调用保留显式标注的兼容重载，HTTP 入口不会使用它。

本轮不新增数据库字段，候选周期使用已有状态日志。Redis 候选增加同 hash tag 的 metadata Hash；旧队列缺少轮次的条目只按第零轮兼容，回池之后会被过滤。滚动升级前需停旧写进程，不能让旧 pop 协议和新 peek 协议混用。

严格个人跨订单在途总量配额仍是前轮明确的边界，本轮没有把 count 资格检查升级为跨订单串行配额。正式 SSO、生产网络及停写迁移演练仍需部署环境；没有新增吞吐或延迟承诺，也没有执行部署、Git 提交或推送。
