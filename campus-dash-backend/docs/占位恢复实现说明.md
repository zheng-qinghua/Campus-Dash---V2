# 抢单占位恢复实现说明

日期：2026-10-20。本文说明本次已落地的存储和恢复协议；完整发布范围及端到端验收以主交付报告为准。

## 持久请求与补偿

`grab_request` 使用校区、跑腿、动作、请求 ID 唯一约束，保存参数指纹、固定租约及不可逆终态。登记租约和提交截止校验均使用 MySQL 时间；业务提交、拒绝与过期处理通过请求行锁串行裁决。成功更新还要求 `lease_until > CURRENT_TIMESTAMP(3)`，防止持锁期间到期的旧线程提交。

`grab_repair_task` 保存投影与精确撤销任务。领取采用条件更新和随机 Worker token，租约过期后可重领，旧领取者不能完成或重试新租约任务。同一事件再次发现差异可以重开 DONE，不能抢占有效 RUNNING；DEAD 需显式调用 `replayDead` 重放。投影任务当前保存任务定位、轮次、目标版本，Worker 每次读取主库最新事实，payload 预留为 `{}`，不会拿旧事件快照初始化 Redis。

请求过期与撤销任务由 `GrabRequestStep` 在同一事务登记。业务状态 CAS 与投影任务由 `JdbcErrandRepository` 同事务登记。当前运行形态是**单库本地事务**，保留 `campus_id` 不代表已经接入真实多库分片。

## Redis 占位协议

v2 使用 `dash:grab:v2:{errandId}:state`，分别保存 committed 与 pending。Lua 原子占位只返回处理中或准入结果，不产生业务成功。版本用十进制字符串比较，ID 与版本不转换为 Lua 浮点数。

- 新版本推进 committed，只清理失效版本或轮次的 pending。
- 同版本重放保留 pending；同版本数据冲突只能经主库复核后校准 committed。
- 撤销同时校验请求记录、执行 token、原版本和轮次，只清 pending，不增加名额，也不修改 committed；即使 pending 不存在仍写墓碑，拦截晚到线程。
- 状态缺失或 INIT 时，普通投影事件不能直接建 READY。重建必须先获取带截止时间的 build token，再读主库，只有当前 token 能发布。
- 请求成功后仍残留的同版本 pending 也会登记精确撤销。先同步 committed，再清理该 token，避免同版本重放永远保留无效占位。

活跃状态巡检按校区、状态、固定主键上界推进持久游标。有效 PROCESSING 占位保留；租约到期或旧版本请求先经过数据库终态裁决。未知或损坏的占位只记录诊断错误，不猜测释放；本页其他任务继续检查，但错误页水位保留，修复异常后再前进。

## 迁移方式

空库使用 `docker/init.sql`。既有库使用 `docker/migrate-grab-reliability.sql`，可重复执行，保留旧数据、旧请求唯一守卫和历史占用事实。新增字段包括 `errand.confirm_deadline`、`grab_record.request_record_id`、`local_message.campus_id`。

历史 LOCKED 任务的截止时间必须先核实原确认窗口。确认历史配置为 300 秒后，在同一 MySQL 会话中执行：

```sql
SET @legacy_confirm_timeout_seconds = 300;
SOURCE docker/migrate-grab-reliability.sql;
```

未设置该变量时，脚本不猜测历史 deadline。末尾结果集列出未回填 LOCKED 与历史多名额任务，协议切换前必须处置。消息校区只通过可关联任务回填，无法关联或毒消息保持 NULL，不统一补成某个校区。历史 `grab_record.request_record_id` 保持 NULL，不生成虚假的历史请求成功记录。

上线时暂停任务写入口、排空旧 Worker，再迁移和启用 v2。回滚保留新表，不让旧 Lua 与 v2 混写，不删除幂等结果，不使用 FLUSHALL。

## 已执行验证

本次存储验证使用本机 Docker 中真实 MySQL 8 与 Redis 7，Redis 端口 6380、MySQL 端口 3307。JDBC 测试创建独占随机库并只清理自己的库；不会领取或修改用户业务库的补偿任务。

| RedisGrabProjectionIT | 9 | 0 | 0 | 0 |
| JdbcGrabReliabilityIT | 9 | 0 | 0 | 0 |
| GrabRecoveryUseCaseTest | 5 | 0 | 0 | 0 |
| RocketMqTimeoutReliabilityIT | 3 | 0 | 0 | 0 |

真实 Redis 覆盖并发唯一占位、同版本保留、A→B→回池→C、旧撤销不影响新 token、撤销墓碑、到期占位需 DB 裁决、INIT 接管与旧构建者失效、旧事件不能初始化、超过 JavaScript 安全整数范围的版本比较。

真实 MySQL 覆盖作用域唯一约束、终态不可反转、到期禁止成功、过期与补偿原子回滚、请求行锁、Worker 租约、DONE 重开、DEAD 受控重放和固定上界游标。迁移分别验证空库初始化和旧结构升级，均重复执行；包含历史毒消息与明确配置后的 deadline 回填。

提交结果未知用例使用测试 TCP 代理，收到 MySQL 的真实 COMMIT OK 包后丢弃响应并断开客户端。调用方收到事务异常，主连接仍能查询到请求 SUCCEEDED、已占业务名额、唯一占用记录和待修复任务，证明**连接异常不能用来推断事务已经回滚**。该测试验证数据库故障窗口，不能代替整个 HTTP/MQ 链路验收。

真 RocketMQ 验证使用专属 DELAY topic、消费组及随机数据库，不启动常驻 Worker 或定时扫描。真实 `TimeoutTransferConsumer` 已验证提前消息无效、到期 A→B→回池、重复旧轮次无效、缺少新字段的旧 payload 仍按 DB deadline 处理。另将测试专用 Producer 实际关闭，确认发送失败后本地消息保持 PENDING，由显式调用数据库扫描恢复；此项是客户端不可用故障，不能描述为已停止整个 Broker 集群。

测试数据源同时设置 `connectionTimeZone=UTC&forceConnectionTimeZoneToSession=true`，保证数据库 NOW 与 JDBC DATETIME 解析使用同一时区。首次真 MQ 验证暴露了只改 JDBC 时区而未改 session 的测试装配错误：任务截止时间被平移 8 小时。已统一会话时区，保留原到期和重复执行断言后重跑通过。生产既有 `serverTimezone=Asia/Shanghai` 配置未因此迁移历史时间语义。

`TimeoutTransferStep` 现在读取 `dash.mq.topic.confirm-timeout`，事务中登记和提交后发送使用同一 topic 配置；专用 topic 验收没有将消息发送到业务消费组。

复现命令：

```bash
mvn -pl dash-infrastructure -am -Dtest=RedisGrabProjectionIT,JdbcGrabReliabilityIT \
  -Dsurefire.failIfNoSpecifiedTests=false -DrequireMiddleware=true test
mvn -pl dash-application -am -Dtest=GrabRecoveryUseCaseTest \
  -Dsurefire.failIfNoSpecifiedTests=false test
# 需先全量 install，使 worker 使用当前应用层与基础设施层版本。
mvn -pl dash-worker -Dtest=RocketMqTimeoutReliabilityIT -DrequireMQ=true test
```

`requireMiddleware=true` 时中间件缺失直接失败，不把跳过当成验收通过。本说明中的 MQ 验证仅代表本机测试条件，不宣称已完成跨实例网关、生产身份接入或性能容量验证。
