# 网关、跑腿限流与身份接入说明

## 交付边界

已新增独立 `dash-gateway` 进程，版本使用 Spring Boot 3.5.8 / Spring Cloud 2025.0.3。网关不依赖业务数据库、MVC Controller 或业务 Service。业务服务继续自行校验 Bearer 身份，服务层按可信跑腿 ID 使用 Redis 共享双桶；网关使用共享路由桶及来源 IP 桶。

正式身份代码使用 Spring Security 的 OIDC 授权码客户端，启用 PKCE，标准客户端校验 state、nonce、签名、issuer、audience 和有效期。验证通过后，以服务端配置的 `(issuer, subject)` 绑定查询本地用户，再签发已有 Session/JWT。缺少映射、重复映射、非正数用户均拒绝。真实校园 issuer、client 凭证、回调地址与账号映射尚需提供并做真实环境联调；本机模拟身份源测试不能代替正式联调。当前 OIDC 回调返回 JSON 会话响应，前端完整 SSO 登录交互需要按实际身份源接入方式联调。

## 入口和故障响应

- 网关默认端口 `8090`；业务服务默认仅监听 `127.0.0.1:8080`。容器内通过 `DASH_BIND_ADDRESS=0.0.0.0` 绑定内部网络，Compose 的 `app` 不发布宿主机端口。
- 每次 HTTP 抢单，包括相同请求 ID 的重试，都消耗预算。拒绝响应为 HTTP 429，并返回向上取整秒数的 `Retry-After`。后续业务失败不退还已消耗的入口额度。
- 跑腿两个桶先同时判断，再原子扣减；不同网关规则顺序扣减，不声称跨 Redis slot 全局原子。
- Redis 连接、脚本、超时等异常返回 HTTP 503，不能当作额度充足。结果查询使用独立预算，并允许受本机预算限制的恢复查询。
- 默认来源为 socket 的直接对端。只有 `dash.gateway.trusted-proxies` 精确 IP 白名单内的代理能提供 `X-Forwarded-For`；从右向左寻找第一个不可信跳点。部署代理必须追加真实上游地址，不能透传客户端自声明链。
- 网关清理外部 `X-User-Id`、`X-Runner-Id`、`X-Campus-Id`、`X-Internal-Token` 及转发身份相关头。
- 公网 `/api/internal/**` 一律拒绝，含路径编码和路径参数变种；后端内部接口还要求至少 32 字节的 `X-Internal-Token` 服务凭证。空配置关闭内部入口，普通用户 Bearer 无权访问。
- 浏览器可读取 `Retry-After`。网关 CORS 要先于拒绝响应执行，否则浏览器会把 429 隐藏为 CORS 错误。

## 参数

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `dash.grab.runner-limit.rate / burst` | `2 / 4` | 单跑腿跨任务每秒补充量 / 容量 |
| `dash.grab.runner-limit.errand-rate / errand-burst` | `0.5 / 2` | 单跑腿单任务预算 |
| `dash.grab.runner-limit.query-rate / query-burst` | `5 / 10` | 查询独立预算 |
| `dash.grab.runner-limit.recovery-query-per-second` | `10` | Redis 故障时本机查询预算 |
| `dash.gateway.route-rate / route-burst` | `1000 / 2000` | 单类路由共享预算 |
| `dash.gateway.ip-rate / ip-burst` | `100 / 200` | 来源 IP 预算，保留校园 NAT 余量 |
| `dash.gateway.auth-ip-rate / auth-ip-burst` | `2 / 10` | 登录、刷新、OIDC 来源预算 |
| `dash.gateway.max-concurrent` | `1000` | 单网关同时处理上限 |
| `dash.gateway.redis-timeout-ms` | `300` | 网关 Redis 最长等待时间 |
| `dash.auth.demo-login-enabled` | `false` | 演示 userId 登录开关 |
| `dash.auth.internal-token` | 空 | 内部接口服务凭证，空值拒绝全部 |

参数为初始保护值，需用真实校园 NAT、重试和高峰流量调优。现有 Sentinel 仍负责单实例热点任务保护。Redis 桶采用 Redis TIME，并保留时钟高水位，避免回拨时重复补充。

## 本地演示

从工程根目录执行完整构建后，显式开启 `local` profile 才可使用旧演示登录。未选择 profile 时，`POST /api/auth/login` 不会给任意 userId 签发令牌。`test`、`bench` 同样必须显式选择，生产混入这些 profile 并启用演示能力会启动失败。

```bash
mvn install
mvn -pl dash-bootstrap spring-boot:run -Dspring-boot.run.profiles=local
mvn -pl dash-gateway spring-boot:run
```

通过网关调试时，前端代理应指向 `http://127.0.0.1:8090`。Session 使用 demo/live 独立命名空间；JWT issuer 自动包含 demo/live 环境后缀，Refresh/吊销键同步隔离。直接切换为正式配置后，旧演示令牌不能继承正式身份。JWT 模式必须通过 `DASH_JWT_SECRET` 注入非空、至少 32 字节的随机密钥；各 profile 均不提供固定示例密钥。

## 正式 OIDC 与容器入口

1. 复制 `docker/identity.example.yaml` 到仓库外受控路径，填入实际 issuer、client、绝对 HTTPS 回调地址及服务端用户绑定。模板没有真实凭证，不能直接用于上线。
2. 使用身份源已登记的绝对回调地址 `/login/oauth2/code/campus`；浏览器从 `/oauth2/authorization/campus` 发起授权。令牌不会放进 URL。
3. 将 `DASH_IDENTITY_CONFIG` 指向配置文件，设置 `DASH_RUNTIME_PROFILE=prod`。未开启正式身份源时，生产 API 进程拒绝启动。后台 worker 没有交互登录端点，不要求配置 OIDC 客户端。
4. 先构建 JAR，再合并 Compose 启动。只映射 gateway 业务端口，业务 app 仅容器内可达；不要额外为 app 发布 8080。

```bash
mvn install
cd docker
docker compose -f docker-compose.yaml -f docker-compose.ingress.yaml build
docker compose -f docker-compose.yaml -f docker-compose.ingress.yaml up -d
```

此 Compose 是入口网络和进程示例。TLS、真实身份凭证、MQ 的容器可达 broker 广播地址，以及现有数据库迁移须按实际环境配置并验证。数据库口令通过 `SPRING_DATASOURCE_PASSWORD` 注入，Compose 将它映射到 MySQL 的 `MYSQL_ROOT_PASSWORD`，模板不提供默认口令；完整说明见 [凭证配置与发布脱敏](凭证配置与发布脱敏.md)。

## 验证范围

新增测试覆盖：两个服务实例共享同一跑腿双桶、任一桶拒绝不扣另一个桶、查询独立预算、Redis 异常关闭写入、时钟回拨、两个网关共享额度、脚本错误、来源与身份头伪造、内部端点阻断、429/503 与 `Retry-After`、生产配置守卫、demo/live JWT 隔离、并发刷新仅一次成功，以及标准 OIDC 的本机签名回调流程。真实 Redis 测试需要 `127.0.0.1:6380`；缺失时会标记跳过，不能据此宣称完成 Redis 验证。

## 旧压测客户端迁移

`SpikeLoadClient` 仅在直接连接本机 `bench` profile 时使用演示身份头；该 profile 显式开启 Header identity，生产守卫会禁止混入生产。新抢单体包含 `expectedRound: 0`，与每次新发布任务的初始轮次一致；请求 UUID 在构建该请求时生成，不做自动换号重试。当前只允许 `slotTotal=1`。

`CacheLoadClient` 从 `DASH_INTERNAL_TOKEN` 读取服务凭证，只对 `/api/internal/**` 附加凭证；启动前缺失即失败。内部接口不会经过公网网关。`CacheLoadClient` 和 `RampLoadClient` 可用 `DASH_BENCH_TOKEN` 指定预先取得的会话，未指定时需要显式启用的演示登录。现有 SQL/cleanup 脚本无 HTTP 抢单调用，未添加无关协议逻辑。
