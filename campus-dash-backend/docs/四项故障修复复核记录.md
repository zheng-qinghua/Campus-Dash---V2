日期：2026-10-20。范围是上一轮新增的自动结算到期校验、资金半消息未知结果处理、Redis 鉴权依赖异常和 Bloom 故障恢复。原始基线见 [异常故障注入验收记录](异常故障注入验收记录.md)。

## 发现与处理

### 鉴权遗漏 Redis LOADING / BUSY

Redis 恢复数据或执行长脚本时，Lettuce 分别抛出 RedisLoadingException / RedisBusyException；Spring Data Redis 将它们包成 RedisSystemException，原拦截器仅识别连接失败和查询超时，因此仍会返回通用 500，缺少退避信息。

Session 与 JWT 适配器现在共享 AuthRedisRead，只把这两种明确的临时故障转换为已有的依赖异常，复用 HTTP 503 + Retry-After。WRONGTYPE 和编程异常原样保留，空令牌、失效 Session、过期/畸形 JWT 仍拒绝认证。该契约指业务 HTTP 请求的身份解析，不泛化为登录、刷新和 WebSocket 所有入口。

### 负缓存可能遮挡已提交订单

Bloom 阴性开始回源后，不存在的 ID 会写短期空值缓存。若查询发生于发布提交之前，或者该查询的回填晚于发布提交，缓存仍可能暂时表示不存在。详情 Controller 原先在空缓存命中时提前返回 ERRAND_NOT_FOUND，跳过了已有的实时数据库读取。

现在详情接口始终由现有主键查询确定存在性，并从同一数据库聚合生成状态、角色与 availableActions；负缓存无权否决已提交订单。缓存查询接线保留，用于已有缓存实验和观测；正缓存路径原有的数据库读取次数不变。空缓存命中的真实 HTTP 详情也需要一次数据库确认，不能将缓存用例的回源计数宣传为 HTTP 的实际数据库次数。

详情未命中时也移除不再参与裁决的同步 Bloom 查询，避免只为 DEBUG 观察而额外等待 Redisson；布隆登记与显式诊断接口保留。

## 未发现新增付款竞态的依据

- delivered_at 只在 PICKED_UP → DELIVERED 写入，当前状态图没有返回 DELIVERED 的路径。自动入口通过到期校验后，争议若抢先提交，后续状态读取或资金事务 CAS 会阻断结算，托管状态在同一事务中回滚。
- 人工与自动结算仍共用托管 CAS、订单 CAS、唯一流水约束。针对确定性交错核对实际收款人、余额、资金流水及信用事件。
- 本地资金事务异常仍保留半消息并传播原异常；主库读取失败返回 UNKNOWN，主库恢复且流水存在后回查 COMMIT。没有将异常重新误判为明确回滚。
